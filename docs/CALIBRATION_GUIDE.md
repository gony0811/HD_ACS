# 도면↔맵 캘리브레이션 절차서 (운영자용)

> 로봇(SLAM) 위치를 화물창 도면 위에 **정확히** 표시하기 위한 1회성 설정 작업.
> 층(L1~L4)마다 한 번씩 합니다. 코드 지식은 필요 없습니다.

---

## ⭐ 딱 하나만 기억하세요 — 좌표 방향

캘리브레이션에 넣는 **도면 X / 도면 Y** 는 아래 방향을 따릅니다.
(화면 우측 상단 **방위 큐브**에도 `+X 선수 / +Y 좌현` 이라고 늘 표시됩니다.)

```
                    우현 (도면 Y −)
                        │
        선수 ─────────── ● ─────────── 선미
       (도면 X +)     중앙(0,0)      (도면 X −)
                        │
                    좌현 (도면 Y +)

  (선수를 바라보면 왼쪽=좌현, 오른쪽=우현 — 앱 화면과 동일한 방향)
```

| 축 | + 방향 | − 방향 | 0 (원점) |
|----|--------|--------|----------|
| **도면 X** | **선수** | 선미 | 탱크 **중앙** |
| **도면 Y** | **좌현** | 우현 | 탱크 **중앙** |

**한 줄 규칙: “선수·좌현으로 갈수록 +, 중앙이 0.”**

> ❗ 가장 흔한 실수: **SLAM 맵 화면에서 재서** 넣는 것.
> SLAM 맵은 축 방향이 이 규칙과 **반대(선미=+, 우현=+)** 일 수 있어, 그대로 넣으면
> 로봇이 **정반대 위치(선미/우현)에 벽을 뚫고** 표시됩니다.
> 좌표는 반드시 **도면(탱크 실측) 기준**으로, 위 규칙대로 만드세요.

---

## 준비물
- 탱크 **전체 길이(선수↔선미)** 와 **전체 폭(좌현↔우현)** 치수
- 기준점 **3곳**(가급적 넓게 퍼지게: 예 - 한쪽 구석, 반대쪽, 중앙 부근)
- 각 기준점까지의 **실측 거리**(벽에서부터)
- 로봇을 각 기준점에 세울 수 있는 환경(현장) — *캡처는 로봇이 그 자리에 있어야 함*

---

## 도면 좌표 만드는 법 (핵심)

각 기준점마다:

1. **선수 벽**에서 그 점까지 거리 = **a** (m)
2. **좌현 벽**에서 그 점까지 거리 = **b** (m)
3. 계산:
   - **도면 X = (탱크길이 ÷ 2) − a**
   - **도면 Y = (탱크폭 ÷ 2) − b**

> 이렇게 하면 자동으로 “선수 쪽 +, 좌현 쪽 +, 중앙 0” 규칙이 맞습니다.

### 넣기 직전 30초 자가 점검 (이것만 지켜도 실수 0)
- 그 점이 **선수 쪽**이면 → 도면 X 가 **+** 인가?
- 그 점이 **선미 쪽**이면 → 도면 X 가 **−** 인가?
- 그 점이 **좌현 쪽**이면 → 도면 Y 가 **+** 인가?
- 그 점이 **우현 쪽**이면 → 도면 Y 가 **−** 인가?

→ 하나라도 반대면 **부호가 틀린 것**. 넣지 말고 다시 계산.

## UI 조작 절차 (계획 ▸ 캘리브레이션 탭)

1. 상단 **층 선택**(예: L4) — 로봇이 보고 중인 층과 같아야 함
   - “로봇 보고 위치 …” 줄이 그 층으로 떠야 정상. (아니면 먼저 **수동 층 변경**)
2. 로봇을 **1번 기준점**으로 이동
3. **도면 X / 도면 Y** 에 위에서 만든 값을 입력 → **[현재 위치 캡처]**
   - (맵 X/Y 는 자동으로 로봇 현재 SLAM 값이 들어갑니다)
4. 2번, 3번 기준점도 같은 방식으로 캡처 (총 3점)
5. **[계산(solve)]** 클릭
6. 하단 결과 확인:
   - **RMS 가 0.05 m 이하**면 양호 (넘으면 경고가 뜸 → 재캡처 권장)
   - RMS 가 크면 거리 측정/부호를 다시 점검

## ✅ 최종 검증 (반드시 하세요)

계산이 끝나면 **눈으로 확인**합니다. 이게 마지막 안전장치입니다.

1. **운영 탭 3D 뷰**로 이동, 로봇이 있는 층 선택
2. 로봇 마커가 **실제 로봇이 있는 위치·방향과 같은 곳**에 있는가?
   - 선수 쪽에 있으면 화면에서도 선수 쪽
   - 좌현 벽 근처면 화면에서도 좌현 벽 근처
3. 마커가 **탱크 안**에 있는가? (벽을 뚫거나 밖으로 나가면 ❌)
4. **뱃머리(방향 화살표)가 실제와 같은 쪽을 보는가?**

> ⚠ 4번을 빠뜨리지 마세요. **180° 어긋남은 마커가 탱크 안에 그대로 남습니다**(탱크가 중심 대칭이라
> 선수/좌현이 선미/우현으로 옮겨가도 여전히 벽 안쪽). "밖으로 안 나갔으니 맞다"로 판단하면 놓치고,
> 이때는 **방향이 반대로 보이는 것**이 유일한 단서입니다.

> 하나라도 안 맞으면 아래 “문제 해결”로.

## 문제 해결

| 증상 | 원인 | 조치 |
|------|------|------|
| 로봇이 **정반대(선미↔선수, 좌현↔우현)** 로 표시 + **뱃머리 방향도 정반대** | 도면 X·Y **부호 방향**을 반대로 넣음(SLAM 맵 기준으로 재서 등) = 180° 회전 | 세 점 모두 **부호 반전** 후 다시 계산. 재측정 없이 고치려면 아래 “이미 잘못 저장된 경우” |
| 위치·방향이 **90° 돌아감**(선수/좌현 → 선미/좌현처럼) | CAD 도면 프레임(선수=+Y) 그대로 입력 | 세 점을 앱 프레임으로 −90° 변환 후 재계산. 또는 아래 도구 `--deg ±90` |
| 방향은 맞는데 **위치만** 벗어남 | 원점(중앙) 기준이 틀림 / 거리 측정 오차 | 원점을 **탱크 중앙**으로, 거리 재확인 후 재캡처 |
| **RMS 경고**(0.05m 초과) | 거리 측정 오차, 점이 한 줄로 몰림 | 기준점을 더 넓게 퍼뜨려 재캡처 |
| **캡처가 안 됨(경고)** | 로봇 보고 층 ≠ 선택한 층 | 로봇 층 확인 또는 **수동 층 변경** 먼저 |
| 앱에서 계산했는데 3D가 **안 바뀜** | — | 계산 성공 시 즉시 반영된다. 그래도 그대로면 아래 행 |
| **DB에서 직접** 고쳤는데(교정 도구·SQL) 화면이 그대로 | 화면이 T_W_D를 **10초 캐시** | 10초 뒤 로봇 state가 들어오면 자동 반영. 더 빨리 보려면 프로젝트 다시 열기 |
| 10초 넘게 기다려도 그대로 | ① `--apply` 를 안 했다(미리보기만) ② **다른 층**만 고쳤다(로봇이 보고하는 mapId 확인) ③ 회전 오차가 아니다(거울·축척) | 계획 ▸ 캘리브레이션의 **로봇 표시** 줄로 대조(또는 `tools\rotate_map_calibration.ps1 <mapId>` 미리보기). 층은 로봇 상태 카드의 보고 층으로 확인 |

## 이미 잘못 저장된 경우 — 회전만 되돌리기

기준점 측정값은 맞는데 **도면 좌표를 돌아간 프레임으로 입력**해서 저장된 경우(위 표의 1·2행),
현장에서 다시 측정하지 않고 회전만 교정할 수 있습니다.

### 앱에서 (권장) — 계획 ▸ 캘리브레이션 (T_W_D)

1. 층을 고릅니다(**로봇이 보고하는 층**. 로봇 상태 카드의 `층(mapId)` 확인)
2. **도면 좌표 프레임 교정 (회전)** 에서 `180° 회전`(또는 `+90°`/`−90°`)
   — 기준점의 도면 좌표만 돌리고 맵 좌표(현장 측정값)는 그대로 두고 다시 계산합니다
3. 바로 위 **로봇 표시** 줄이 실제 위치·방향과 맞는지 확인
   (`선수/좌현 (11.64, 2.68) · 방향 좌현(88.0°)` 형식)
4. 틀렸으면 반대 부호로 되돌리고, 맞으면 **파일 ▸ 저장**
5. 한 점만 잘못 입력한 경우에는 목록에서 **행을 클릭**(또는 `편집`)하면 값이 입력칸에 들어옵니다 →
   고친 뒤 `선택 점 수정` (기준점 id가 유지돼 대응쌍이 끊기지 않습니다)

> **파일 ▸ 저장을 빠뜨리지 마세요.** `.hdacs` 프로젝트 파일은 캘리브레이션 기준점을 함께 저장하고,
> 파일을 열 때 서버의 기준점을 **파일 값으로 되돌린 뒤 재계산**합니다. 저장하지 않으면 다음 열기에서
> 교정이 통째로 사라집니다.

### 명령줄에서 (서버 직접 접근·여러 층 일괄)

현장 서버는 **Windows**이므로 PowerShell 판을 쓰십시오(같은 동작·같은 출력).
`export PGHOST=...` 는 bash 문법이라 PowerShell 에서 `'export' 용어가 ... 인식되지 않습니다` 오류가 납니다.
스크립트 실행이 보안 정책(`PSSecurityException`)으로 막히면 `-ExecutionPolicy Bypass` 로 한 번만 우회합니다:
`powershell -ExecutionPolicy Bypass -File .\tools\rotate_map_calibration.ps1 CT1-L4`

```powershell
# 서버에서 (폐쇄망, PowerShell). 미리보기 — 아무것도 바꾸지 않습니다
cd C:\HDACS\src      # 저장소를 둔 곳. 없으면 개발 PC에서 실행하고 -PgHost 로 서버 지정
.\tools\rotate_map_calibration.ps1 CT1-L1 -PgUser hdacs      # 비밀번호는 물어봅니다

# 미리보기의 "after" 가 실제 로봇 위치·방향과 맞으면 적용
.\tools\rotate_map_calibration.ps1 CT1-L1 -Apply
.\tools\rotate_map_calibration.ps1 CT1-L1,CT1-L2,CT1-L3,CT1-L4 -Apply   # 전 층 같은 실수였다면
.\tools\rotate_map_calibration.ps1 CT1-L4 -Deg -90 -Apply               # 90° 오차면
```

접속 정보는 매개변수(`-PgHost -PgPort -PgDatabase -PgUser -PgPassword`)나 환경변수
(`$env:PGPASSWORD='...'`)로 줍니다. `psql` 이 PATH 에 없어도
`C:\Program Files\PostgreSQL\16\bin` 을 자동으로 찾습니다.

Linux/macOS 또는 Git Bash 에서는 같은 기능의 bash 판을 씁니다.

```bash
export PGHOST=localhost PGPORT=5432 PGDATABASE=hdacs PGUSER=hdacs PGPASSWORD=***
tools/rotate_map_calibration.sh CT1-L1                                # 미리보기
tools/rotate_map_calibration.sh --apply CT1-L1
tools/rotate_map_calibration.sh --apply CT1-L1 CT1-L2 CT1-L3 CT1-L4
tools/rotate_map_calibration.sh --deg -90 --apply CT1-L4
```

미리보기는 **그 맵을 보고 중인 로봇의 현재 좌표**를 before/after 로 환산해
`선미/우현 (-5.00, -8.00), 방향 선미(180.0°)` → `선수/좌현 (5.00, 8.00), 방향 선수(0.0°)`
처럼 보여줍니다. before 가 지금 화면과 같고 after 가 실제와 같으면 그 회전량이 맞습니다.

적용 시 **기준점의 도면 좌표도 같은 각도로 회전**하므로, 나중에 누군가 다시 계산(solve)해도
교정이 유지됩니다. 평행이동(t)과 RMS는 바뀌지 않습니다 — 위치가 따로 벗어났거나 측정 자체가
틀렸다면 이 도구가 아니라 재측정(`tools/recalibrate_map.sh`)이 필요합니다.
적용 전 값은 TSV로 백업되고, 되돌리는 SQL도 함께 출력됩니다.

## 부록 — 실제 예시 (CT1, 길이 30.965 m × 폭 17.285 m)

- 중앙(원점) = 길이 ÷2 = **15.483**, 폭 ÷2 = **8.643**

| 점 | 선수벽 거리 a | 좌현벽 거리 b | 도면 X = 15.483 − a | 도면 Y = 8.643 − b | 위치 |
|----|-----|-----|-----|-----|------|
| P1 | 13.470 | 8.635 | **+2.013** | **+0.008** | 중앙 부근 |
| P2 | 8.615 | 14.245 | **+6.868** | **−5.602** | 선수/우현 |
| P3 | 4.225 | 4.075 | **+11.258** | **+4.568** | 선수/좌현 |

→ 셋 다 **선수 쪽이라 X 가 +**, P3는 **좌현이라 Y 가 +**, P2는 **우현이라 Y 가 −**.
자가 점검 규칙과 일치합니다.
