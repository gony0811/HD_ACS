# 아덴트로봇 TARS-M 기술 질의서 (VDA5050 연동 관련)

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-08-28 |
| 목적 | HD_AMR 통합 운영 S/W ↔ TARS-M 인터페이스 확정 (VDA 5050 관제 연동의 전제) |
| 현재 확보 자료 | Modbus TCP 레지스터 맵(매뉴얼), v3 REST Swagger 화면 1장 (`POST /api/v3/robot/go`) |

아래 질의에 대한 회신(가능하면 **v3 REST API 전체 사양서/Swagger JSON**)을 요청드립니다.

## 1. REST API 전반

1.1. **v3 REST API 전체 사양서**(Swagger JSON 또는 문서) 제공 가능 여부 — 전체 엔드포인트 목록, 인증 방식, 기본 포트.

## 2. 좌표 이동 `POST /api/v3/robot/go`

2.1. **응답 스키마** — 성공/실패 시 각각 어떤 body가 반환되는지.
2.2. **동기/비동기** — 응답이 "명령 수리"인지 "도착 완료"인지. 비동기라면 이동 완료/실패를 확인하는 방법(상태 조회 엔드포인트? 콜백?).
2.3. **이동 실패 시 동작** — 목표 도달 불가(장애물·경로 없음) 시 로봇 동작과 실패 통지 방법, 관련 에러코드 목록.
2.4. **`stopFlag` 의미** — true/false 각각의 동작.
2.5. **좌표 프레임** — x/y[m], rz[rad] 가 SLAM 맵 원점 기준이 맞는지, rz가 맵 X축 기준 CCW 라디안인지.
2.6. **이동 중 재호출** — 이동 중 새 `/go` 호출 시 동작(대체? 거부?).
2.7. **이동 중지** — REST로 진행 중 이동을 중지하는 엔드포인트 유무. 없다면 Modbus 주행 정지(Holding 12)가 REST 발행 이동도 정지시키는지.

## 3. 재측위 (Modbus PoseSearch, Holding 20~26)

3.1. **탐색 범위** — 포즈 탐색이 지정 좌표 주변 **국소 탐색**인지 맵 전역 탐색인지, 탐색 반경.
3.2. **완료/실패 판정** — 탐색 완료·실패를 확인하는 방법(레지스터? 소요 시간 상한?).
3.3. **맵 일치율(Input 30)** — 정확한 의미(무엇의 일치율인지), 정상 주행 시 통상 범위, "측위 신뢰 가능" 판단 임계값 권고치.

## 4. 맵 관리 (통합 맵 운용 확인)

배경: 화물창 4개 층을 각각 스캔한 맵을 **1장의 맵으로 병합해(층별 타일 배치) 단일 맵으로 운용**하려 합니다.

4.1. 맵 편집/병합 도구 제공 여부 — 별도 스캔한 맵을 한 맵에 이어 붙이는 기능.
4.2. **최대 맵 크기**(면적/해상도/파일 크기) 제한.
4.3. 단일 맵 내에 물리적으로 분리된 구역(층 타일)이 여럿 있을 때 측위·주행상 제약 여부.
4.4. (참고) 복수 맵 저장·활성 맵 전환 기능이 있다면 그 방법(태블릿 UI/REST) — 통합 맵이 불가할 경우의 대안 확인용.

## 5. 기타

5.1. 로봇 에러 코드(Input 11) 전체 목록.
5.2. WorkStatus(Input 64: 대기/이동/도킹/조그)가 REST `/go` 이동 시에도 동일하게 반영되는지.
5.3. Wi-Fi 로밍 시 TCP(Modbus)/HTTP(REST) 세션 유지 특성 — 두절 시 재접속 권고 방식.
