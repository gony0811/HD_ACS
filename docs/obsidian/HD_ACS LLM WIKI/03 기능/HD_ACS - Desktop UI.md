# Desktop UI

## 2026-09-08 캘리브레이션과 수동 이동

계획 화면의 T_W_D 기준점 입력은 **도면 좌표 입력 → 현재 위치 캡처 → AMR 맵 X/Y 확인·수정 → 기준점 저장 → 계산** 순서입니다. 캡처는 입력란을 채우며 즉시 기준점을 저장하지 않습니다. 맵 X/Y는 m 단위로 직접 입력할 수도 있습니다. 실시간 보고는 편집값을 덮어쓰지 않고, 층 변경 시 편집값을 초기화합니다. 저장 API는 선택적 MapX/MapY를 함께 받으며 두 값이 없으면 기존 로봇 보고값을 사용합니다.

운영 화면(Avalonia)의 수동 이동을 켜면 **도면 X/Y(m)** 입력과 **입력 좌표로 이동** 버튼이 나타납니다. 선택적인 방향(°)은 도면 기준이며 빈 값은 방향 자유입니다. 선택 층 바닥 범위와 유한 숫자를 확인한 뒤 기존 goto API로 전달합니다. 서버의 T_W_D가 위치와 방향을 맵 좌표로 변환합니다.

기존 바닥 클릭·드래그 이동도 사용할 수 있습니다. 수동 이동 중 바닥 위에 커서를 올리면 커서 옆에 `X: 1.23 m   Y: 4.56 m` 형식으로 도면 좌표를 표시합니다. 바닥 밖·커서 이탈·수동 이동 해제 시 표시하지 않습니다.

검증: 캘리브레이션 변경 후 Desktop·App 빌드 경고/오류 0. 이후 수동 좌표 이동·커서 표시 변경 후 Desktop 빌드 오류 0, Telerik NuGet 취약성 정보 조회 실패(NU1900) 경고 1. 이번 변경의 실장비 이동, 실제 화면 조작 및 추가 자동 테스트는 수행하지 않았습니다. 좌표 직접 이동·커서 표시는 Avalonia에 추가했으며 WPF에 같은 UI를 추가한 것은 아닙니다.

관련: [[HD_ACS - 2026-09-08 개발일지]].

## 좌표 입력창 개선

사용자 요청은 P1~P4 u/v 및 x/y/θ NumericUpDown의 최소 너비를 100 이상으로 늘리는 것이었습니다. 대화 초기에 11개 컨트롤에 MinWidth=100을 추가했습니다.

위키 작성 시점의 파일을 다시 읽은 결과, **현재는 MinWidth=150**이며 x/y와 θ가 별도 행으로 나뉘어 있습니다. 정차 이격도 150입니다. 이 후속 변경의 작성자나 작업 시점은 확인하지 않았습니다.

파일: `src/HD.Acs.UI.Desktop/Views/AreaManagementView.axaml`.

## 검증 이력

- 최초 빌드는 기존 산출물 쓰기 권한 문제로 실패했습니다.
- 권한을 높인 기본 출력 빌드는 실행 중인 앱의 DLL 잠금으로 실패했습니다.
- 별도 출력 폴더 빌드는 성공했습니다. NU1900 취약성 정보 조회 경고 2건이 있었습니다.
- 위 성공은 **100 수정 시점**의 결과입니다. 현재 150 상태를 다시 빌드했다는 뜻이 아닙니다.
