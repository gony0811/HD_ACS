# HD_ACS 시스템 아키텍처

> 상태: 핵심 결정 완료 (근거는 `ARCHITECTURE_DECISIONS.md` 참고). 세부 미결 항목은 ⬜ 표기.

## 1. 아키텍처 개요

- **단일 상대 원칙**: HD_ACS의 로봇측 상대는 **HD_AMR 하나**, 인터페이스는 **VDA 5050 하나**다. AMR/협동로봇/검사장비는 HD_AMR이 통합 제어하며, 검사 시퀀스·자세 제어는 전부 HD_AMR 책임 [ADR-001]
- **실행 모델**: 온보드 실행형 — HD_ACS는 미션(Order)을 계획·릴리즈하고, HD_AMR이 이동·검사를 자율 실행 [ADR-001]
- **통신**: VDA 5050 over MQTT [ADR-001], 통신 두절 허용 + 재접속 동기화 [ADR-002]
- **배포**: 현장 이동식 서버 1대, 폐쇄망, 클라이언트 다수 [ADR-003] — 서버는 단일 프로세스 모놀리스 + Mosquitto + PostgreSQL 3개 OS 서비스, 이중화 미도입 [ADR-011]
- **스택**: C#/.NET — ASP.NET Core 서버 + WPF/Web 클라이언트 [ADR-005, 006]

## 3. 서버 컴포넌트 책임

### 시나리오 매니저
- 검사 시나리오 CRUD, 버전 관리, 유효성 검증
- 시나리오 → VDA 5050 Order(nodes/edges/actions) 변환 규칙 보유

### 미션 오케스트레이터
- **Stateless 라이브러리 기반 명시적 상태머신** [ADR-010] — 상태/전이 이벤트를 EF Core로 기록, DOT export로 상태도 자동 생성
- 미션 인스턴스 생성, 상태 머신 관리
- **선릴리즈 전략**: 통신 두절을 전제로 시나리오 전체(또는 큰 구간)를 Base로 릴리즈 [ADR-002]
- **재접속 동기화**: connection 토픽으로 두절/복귀 감지 → 로봇 state(lastNodeId, actionStates) 기준으로 관제 DB 갱신 (robot-is-truth)
- 실패 정책 실행 (재시도/스킵/알람), 비상정지 instantAction 발행 [ADR-007]

### VDA 5050 마스터 어댑터
- MQTT 발행/구독, 메시지 스키마 검증, headerId 시퀀스 관리
- 커스텀 액션 카탈로그 (⬜ Q1): 검사 작업 실행(HD_AMR에 정의된 작업 식별자 참조), 촬영 트리거(위치 파라미터, 성공/실패 응답 매핑) [ADR-004] — 액션의 내부 실행 방법은 HD_AMR 소관이며 ACS는 관여하지 않는다
- robotId 단위 세션 관리 — fleet 확장 대비 [ADR-003]

### 상태 집계/알람
- 로봇 상태·미션 진행률·오류를 집계하여 SignalR 허브로 다중 클라이언트에 푸시
- 임계 이벤트(오류, 배터리, 두절) 알람 발행

### 수행이력/리포트
- 검사 수행 이력 저장: 지점, 위치, 시각, 촬영 성공/실패, 시도 횟수 [ADR-004]
- 미션 단위 리포트 생성, 검사 S/W와 대조 가능한 위치+시각 키 유지 (⬜ Q2)

## 4. 통신 두절 시나리오 (핵심 흐름)

```
정상:   ACS ──order(Base=전체 시나리오)──▶ 로봇
        로봇 ──state(진행 상황, 주기)──▶ ACS ──SignalR──▶ 모든 UI

두절:   connection 토픽 Last Will → ACS가 OFFLINE 표시 (UI 알람)
        로봇은 릴리즈된 Base를 계속 자율 실행 (검사 지속)

복귀:   로봇 ──state(최신 lastNodeId/actionStates)──▶ ACS
        ACS: 관제 DB를 로봇 상태로 동기화, 누락 이력 회수(⬜ 확장 규약)
        UI: ONLINE 복귀 + 진행률 일괄 갱신
```

## 5. API 계층 [ADR-005]

- **REST API** (명령·조회): 시나리오 CRUD, 미션 시작/일시정지/중단, 이력·리포트 조회, 비상정지
- **SignalR 허브** (실시간): 로봇 상태, 미션 진행률, 알람 — 다중 사용자 동시 모니터링 [ADR-003]
- WPF 앱을 포함한 모든 클라이언트는 이 API 계층만 사용 (API-First)

## 6. 클라이언트

- **WPF 운영 앱** (주 화면): 화물창 3D 뷰 + 전개도 기반 시나리오 편집/실행/모니터링 (3D 라이브러리 ⬜ Q5)
- **Web 대시보드 / 태블릿**: 모니터링 중심 (조회 + 알람)

## 7. 설계 원칙

1. **단일 상대·관제-제어 분리**: ACS의 상대는 HD_AMR뿐(VDA 5050 단일 인터페이스). ACS는 "어느 지점에서 어떤 작업을 언제", HD_AMR이 "어떻게"(시퀀스·자세·장비 제어) — 개별 장치 제어 코드 금지 [ADR-001]
2. **두절 내성 우선**: 모든 흐름은 "지금 끊겨도 검사가 계속되는가"를 기준으로 설계 [ADR-002]
3. **robot-is-truth**: 실행 상태의 진실은 로봇에 있고, 관제는 이를 반영한다
4. **API-First**: UI는 교체 가능, 서버 API가 계약이다
5. **fleet-ready**: robotId를 모든 코어 모델의 키에 포함하되, 교통 관리는 범위 외
6. **폐쇄망 자급자족**: 외부 인터넷 의존 요소 금지 [ADR-003]
7. **안전 계층 분리**: 관제 비상정지는 기능적 정지 — 안전 규격 정지는 로봇 측 하드웨어 체계가 담당 [ADR-007]
